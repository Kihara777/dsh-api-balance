# セキュリティポリシー

[中文](../SECURITY.md) | [English](SECURITY.en.md) | 日本語 | [偽中国語](SECURITY.pcn.md)

## サポート対象バージョン

本プラグインは DeepSeek Harness（DSH）ホスト上で動作し、**最新の `main` ブランチのみ**が
セキュリティ修正を受けます。過去のコミットは個別に保守しません——旧版が必要な場合は
ご自身で fork し、保守もご自身で負担してください。

## 脆弱性の報告

セキュリティ問題を**公開 issue で報告しないでください**。GitHub の
[非公開脆弱性報告](https://github.com/Kihara777/dsh-api-balance/security/advisories/new)
チャネル、またはメールで維護者までご連絡ください。

報告には可能な範囲で次を含めてください：影響を受けるバージョン／コミット、再現手順、
期待値と実際の結果、そして想定している脅威モデル（誰が起動でき、どのような前提条件が
必要か）。

## 応答時間

維護者（狐莉）は一級視覚障害を持ち、日常は視覚支援エージェントと協働して開発しています。
**7 日以内**の一次回答を目指しますが、複雑な問題の完全な評価にはさらに時間がかかる
場合があります——ただし、**すべての報告に回答します**。

## 既知の設計境界

以下は**脆弱性ではなく**意図された挙動です。報告前にご確認ください：

| 項目 | 説明 |
|---|---|
| ブラウザの Local Storage からプラットフォームトークンを読み取る | 「プラットフォームトークン」は**ローカルブラウザのログイン状態を自動スキャン**して取得し、**既定で有効・設定で無効化可能**です。読み取るのはトークンのみで、ブラウザ内の他のデータは収集せず、トークンは `0600` でディスクに保存されます |
| トークンスキャンの 6 時間スロットル | `config.browserScanIntervalMs` は既定 6 時間。ウィンドウ内では再スキャンせず、前回のスキャン報告を返します |
| 残高／使用量の照会は外部 API に到達する | `/user/balance` と使用量統計は、プラグインに設定されたトークンで DeepSeek 公式エンドポイントへ要求します——これは本プラグインの**中核機能**であり、データ漏洩ではありません |
| エンドポイントは DSH の `/api` チャネル経由 | 本プラグインの HTTP エンドポイントは、認証と Host authority（`trustedHosts`）の境界を **DSH ホスト**から得ます。プラグイン自身は認証層を持ちません |

## 評価済みの外部報告（クローズ済みを含む）

以下の報告はすべて**項目ごとに確認**し、根拠とともに公開回答しています。**これらを掲載する
のは、後続の報告者が同種の問題を重複して提出せずに済むようにするためです**——いずれかの
結論が誤っていると思われる場合はご指摘ください。再評価します。

| 番号 | 報告内容 | 結論 | 根拠 |
|------|---------|------|------|
| PR #4 / #5（@anupamme、スキャナによる自動生成） | `/token`、`/token/clear`、`/voicepack`、`/tts` にレート制限がないと主張 | **誤検知、未マージ** | 下記「レート制限欠如の報告について」参照 |
| PR #4 / #5 の付随主張 | `/query` にリクエストボディのサイズ上限がないと主張 | **誤検知、未マージ** | その防御は既に `readJsonBody` の **64 KiB** 上限（`lib/index.js`）で提供されています。追加された `content-length` 検査は chunked エンコーディングで迂回でき、`text.length` はバイト数ではなく UTF-16 コード単位です |

### レート制限欠如の報告について

複数のスキャナ報告が一部エンドポイントにレート制限がないと主張しています。**項目ごとに
確認した結果、誤検知と判断しました**。理由は次のとおりです：

**① 記述と diff が一致しません。** PR は `/token`、`/token/clear`、`/voicepack`、`/tts`
の 4 エンドポイントに影響すると主張していますが、その **diff が変更しているのは
`/query` の 1 パスだけ**です。

**② その制限キーは本デプロイ形態では成立しません。** PR は `x-forwarded-for` を
クライアント識別子にしていますが、このヘッダは**クライアントが任意に偽装できる**ものです。
さらに重要なのは、本プラグインへの呼び出しは**同一オリジンのページから DSH の `/api`
RPC チャネル経由**であり、その経路は **`x-forwarded-for` を伴いません**——したがって
すべてのローカル要求が同一の `"unknown"` バケットに入り、**正常なユーザーが自分自身の
制限に先に当たってしまいます**。

**③ 主要エンドポイントには既にスロットルがあります。** `/token` には既に **6 時間**の
サーバー側スロットル（`browserScanIntervalMs`）があり、音声アナウンスには **30 分**の
制限があります。

**④ 本プラグインに高頻度ポーリングはありません。** ソース中で唯一の 30 秒
`setInterval` が実行するのは `isPeakPricing()`（**純粋にローカルな時刻判定**による
ピーク／オフピーク料金のヒント）で、**ネットワーク要求を一切発行しません**。他に 15 分
間隔のポーリングがあります。人間の操作速度で見積もると、最も活発な使い方でも
**毎分 5〜10 回**程度です——スキャナ推奨の毎分 30 回は既にその 3〜6 倍で、人間の操作では
まず到達できません。

**⑤ 本当の境界はアプリケーション層にありません。** エンドポイントへの到達可否は
**DSH ホストの認証と Host authority** が決めます。その境界を突破できる者を毎分 30 回の
制限で止めることはできず、一方でこの制限は通常の更新操作を害します（残高更新を待つ間に
連続クリックするのは正常な行為です）。

**結論とトレードオフ**：この件で**コードは変更しません**。将来本当に防御層が必要になった
場合の正しい方法は、**IP ではなく認証主体ごと**のレート制限（IP は偽装可能）とし、
閾値は**あらゆる人間の操作より十分高く**（例：毎分 60〜120 回）、「暴走スクリプト対策」と
して位置づけることです——そしてアプリケーション層に誰も止められず実ユーザーを害しうる
制限を足すより、ホスト側の境界を先に強化すべきです。

> **上記の結論に誤りがあれば、再現可能な根拠とともにご指摘ください。** 私たちは
> 「まず確認し、次に回答し、根拠を添える」という手順で処理しており、報告を鵜呑みには
> しません。

### 重複提出について

**上表に既出の同一結論が、新しい根拠なしに再提出された場合は、本節を指して直接
クローズします。**

| 受理する | 直接クローズする |
|---------|-------------|
| 上表にない**新規**の問題 | 上表と同一結論で、新しい根拠のない重複報告 |
| 上表のいずれかの結論が**誤り**であることを再現可能な根拠付きで示すもの | 既存の結論を述べ直すだけのもの |
| 同じ主題だが**異なる**脅威モデルや悪用経路 | 同一ルールの再度の自動スキャン出力 |

## サプライチェーンについて

- 本リポジトリは**シークレットを一切含みません**。プラットフォームトークンは実行時に設定
  またはローカルブラウザのログイン状態から取得し、ユーザーディレクトリに `0600` で保存します
- npm パッケージは公開していません（維護者は視覚障害があり、npm の提出手順を単独で
  完了できないため）。GitHub ソースからのインストール、または
  [NixKits](https://github.com/Kihara777/NixKits) の薄いラッパーによる宣言的インストールを
  ご利用ください

場合でも、**確認の過程そのものが実際の改善を生みます**——上表のサイズ上限の確認がその
一例です。
